# Character Roster

建立時間：2026-07-17（新增雞排攤時順手建立，第一份角色設計文件）

三個角色都是 [PlayerCharacter](../scripts/player_character.gd) Resource，數值定義在
`resources/characters/*.tres`。目前系統只支援單一直線投射物、移動中自動射擊，
沒有技能/大招/扇形攻擊——這份文件記錄的是「同一套攻擊模式下的數值定位」，
不是技能設計。

---

## 定位總覽

| 角色 | 檔案 | 定位一句話 |
|---|---|---|
| 熱狗攤 | `hotdog.tres` | 遠距離大顆重砲，慢但每發都有存在感 |
| 珍奶攤 | `bubble_tea.tres` | 高頻小顆騷擾，靈活但單發弱 |
| 雞排攤 | `chicken_cutlet.tres` | 近中距離重擊，全場最高擊退，最容易誤傷隊友 |

雞排攤是這三者裡「風險最高」的：子彈最慢、最貼身（`proj_speed` 全場最低），
但只要打中，敵人飛最遠、玩家中招飛最遠——移動射擊的自動瞄準機制下，
慢速大顆彈很容易打到剛好走進準心的隊友，這是刻意設計，不是數值失衡。

## 已知限制（這次順手發現，沒有動手改）

**marker_shape 只支援 circle/square 兩種**（[player.gd](../scripts/player.gd) `_draw()` 裡硬判斷
`if character.marker_shape == "square": ... else: draw_circle`）。三個角色只能用兩種形狀，
雞排選了跟熱狗共用 `circle`（用顏色區分），不是刻意要弱化辨識度，
純粹是目前的形狀系統撐不住第三種。等第四個角色（章魚燒/臭豆腐）加進來、
或需要更清楚的敵我辨識時，這裡會是第一個要擴的地方——可能要改成
`marker_shape` 存一個 draw callback 名稱，或乾脆換成貼圖而不是程式畫形狀。

**`PlayerCharacter` Resource 本身沒有不夠用的地方，但有結構性邊界。** 雞排攤完全是「調數值」
就做完了，沒有改任何 `.gd` 程式碼——這代表 Resource 抽出來的欄位覆蓋得很完整，驗證通過。
但這也只證明了「同一種攻擊行為、不同數值」這個擴充路徑是通的。如果之後臭豆腐想要
「範圍持續傷害」、章魚燒想要「扇形多發」，那是**攻擊行為**不同，不是數值不同，
現在的 Resource + `player.gd` 架構（單一直線投射物）沒辦法只靠加欄位解決，
屆時需要在 `PlayerCharacter` 加類似 `attack_pattern` 的欄位，並在 `player.gd`/`projectile.gd`
真的分支出新的攻擊邏輯，不是這次「加角色只調數值」能涵蓋的範圍。
